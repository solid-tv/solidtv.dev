LightningJS alternative

A faster alternative to LightningJS and Blits

LightningJS set the bar for TV UIs on constrained hardware, and SolidTV builds on that foundation. It began as the SolidJS integration for Lightning 3 and now ships its own renderer: a fork of Lightning 3 rebuilt for 60fps on the low-end hardware TV apps really run on.

Side by side

SolidTV compared with upstream Lightning 3 and Blits

Upstream Lightning 3 / Blits SolidTV
Per-frame work The update loop does real work every frame for nodes that haven't changed Static and lightly-animated subtrees cost almost nothing, with translate-only and scale-only fast paths
Garbage collection Allocations inside the render loop cause GC stutter on low-end devices Allocation-light hot paths: lazy animation maps, a slim glyph layout and a lean texture upload queue
Components Blits adds an extra parent node for every component, doubling the node count Components compile away, so a component costs the same as the nodes inside it
Size Blits is about 80KB larger ~12kb minified + gzipped for the framework

Inside the renderer

What changed in the fork

Owning the renderer means fixes ship when your app needs them, not once a quarter. A short tour of what has landed since the fork:

Text rendering

A cached SDF text layout, cap-height centering for labels that look centered, verticalAlign that works in flex layouts, and emoji that keep their colors.

Shaders & visuals

A self-animating RadialProgress shader, a single-pass Blur, borders that default to outside, and gradient parity between WebGL and Canvas.

Images & SVG

DPR-aware SVG rasterization, source-region crops, zero-copy uploads, and image decoding that overlaps with GPU upload.

Animation & tooling

Adaptive durations that stay correctly timed at variable frame rates, plus an inspector that shows component names and source locations.
